Let me explain how this lab works. For every column in your dataset, you will answer five questions, and the answers go into a small table that we call a data dictionary. This sounds simple, but it is the step that prevents the most expensive mistakes later, such as averaging a category code or one-hot encoding a number. Open any dataset in Jupyter, run df dot info and df dot head, and keep that output on screen while you follow the video.
#1
Let me add how each question connects to code. For the level of measurement, you decide by reading the column name and a few values. For discrete versus continuous, df dot nunique helps, because a handful of unique whole numbers suggests a count. For structure, you check the file format and whether pandas read it in directly. For text, you look at object columns with long strings. And for time, you try pd dot to datetime on any column that looks like a date. Together these take less than five minutes on a new dataset, and they save hours.
#2
Let me give some more examples from datasets you may know. In the Titanic data, passenger class is ordinal, because first is better than third, but sex and port of embarkation are nominal. Age and fare are ratio, because zero means none. In a weather dataset, temperature in Celsius is interval, and rainfall in millimetres is ratio. Notice that the same dataset mixes all four scales, so you must decide column by column. Never decide for the whole table at once.
#3
Let me give you a trap to watch for. A column called rating with values one to five looks numeric, and pandas will happily compute its average. But is the gap between one and two stars the same as between four and five? Probably not. So it is ordinal, and the median or the share of each rating is safer. Another trap: a postal code is written as digits but is nominal, because adding two postal codes means nothing. Ask what the number means, not what it looks like.
#4
Let me show how to check this in code. Use df dot nunique to see how many different values each numeric column has. A column with only five different whole numbers probably is a count or a rating. Then check df of the column dot dtype. If it is an integer, it may be a count. If it is a float, it is likely measured. One more trick: a float column where all the values happen to be whole numbers may have been a count that was stored as a float because of missing values, so look at the values themselves.
#5
Let me give a concrete example of reading a file. If your file is dot csv, df equals pd dot read csv works immediately and every row has the same columns. If your file is dot json, pd dot read json may work for simple cases, but nested records need json normalize to flatten them. For a log file, you might need regular expressions to split each line into fields. The more work you need before you get a clean table, the more semi-structured the source is, and the more care you should take with a data dictionary.
#6
Let me explain the first steps with text columns in code. Take a review column and make it lowercase with str dot lower. Split it into tokens with str dot split. Count how many tokens each review has with str dot len, and look at its distribution, because very short and very long reviews often behave differently. Notice that you are already doing exploratory analysis on text, using the same ideas as for numbers: counts, distributions, and outliers. In module four we will turn tokens into numeric features.
#7
Let me explain how to plot it. Make sure the date column is a proper datetime and set it as the index. Then plot the value against the date with df dot plot. To see a trend, add a rolling mean with a window such as twelve months. To see seasonality, group by month, using df dot groupby of the month, and compare the average per month. If the monthly averages differ a lot while the rolling mean is flat, you have seasonality without much trend. If the rolling mean moves steadily, you have a trend.
