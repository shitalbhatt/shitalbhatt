#1
Let me explain the two checks. The variance threshold removes columns that barely change. It is meaningful for zero-one dummy columns, where a variance near zero means almost all rows have the same value. For continuous columns, variance depends on units, so a rate between zero and one can look constant when it is not. The correlation check uses the correlation matrix, and takes only the upper triangle so each pair appears once. Product related and total pages have a correlation of point nine nine seven, almost identical. In such cases keep the one that is easier to explain, and drop the other.
#2
Let me explain the code. SelectKBest takes a score function and k. With f classif, it computes the F statistic for each feature, and with mutual info classif, it estimates mutual information. You call fit on the training data and the target, then get support to see which columns are selected. Put the names and scores in a data frame sorted by score, so you can read the ranking. Two different statistics, one linear and one that can detect non-linear relations, agree on the top features, which is good evidence that the signal is real.
#3
Let me explain the settings. RFE takes the estimator, the number of features to keep, and a step, which is how many features to drop in each round. We use logistic regression and ask for ten features. SequentialFeatureSelector with direction forward and n features to select ten adds one at a time, scoring by cross-validation on the training rows. They give different lists, and that is normal, because features that overlap can substitute for each other. The time cost is clear, seventeen and twenty-five seconds here, and it grows quickly with the number of features and the size of the data.
#4
Let me explain each of the two. For L one, we fit LogisticRegression with penalty l one, solver liblinear or saga, and C equal to point oh two. Then we count the coefficients that are not zero, which is twenty. The remaining sixty-five features are dropped by the model itself. For the random forest, we fit RandomForestClassifier, read feature importances, sort, and take the top ten. Remember that importances in a forest are spread among related features, so if several features carry the same signal, each shows a smaller importance than the signal deserves.
#5
Let me explain the pattern. We create a dictionary where each key is the name of a method and each value is its list of selected columns. The evaluate function takes a list of columns, fits a logistic regression on the training rows, and returns the test AUC and F one score. Then we apply it to every entry with a dictionary comprehension, and put the results in a table sorted by AUC. This way, the comparison is fair, and the code is short. It is a pattern you can reuse for any comparison of feature sets.
#6
Let me explain how to interpret this result. Ten features chosen by forward selection do as well as all eighty-five. That means seventy-five columns were not needed. The filters and the random forest did worse with their top ten, not because the methods are bad, but because their lists contained five versions of the same signal, so ten columns carried only about six different ideas. The wrappers and L one handle redundancy, so they picked a more diverse set. The lesson is to check the diversity of what you keep, and not only each feature's score.
#7
Let me explain how this table is built. For each of the six methods, we have a list of selected features. We count, for each feature, in how many lists it appears, and sort by this count. Features that all methods choose are very likely to matter. Features chosen only by one method may depend on that method's assumptions. When you write a report, you can say that the page value family was chosen by every method, and that is a much stronger statement than saying one method chose it.
#8
Let me explain why this is a valuable negative result. The Pima data has zeros in places where zero is impossible, like blood pressure, so we treat those as missing, and fill them with the median. We create flags and ratios exactly as in the lecture. The flags separate the groups strongly, from twelve percent to seventy-six percent diabetic. Yet the test AUC does not change, because glucose, body mass index and age already express this information. So building features is not always useful, and testing each time is the only way to know. A report that shows a feature did not help is honest and valuable.
#9
Let me explain the meaning. Five of fourteen features give almost the same AUC as all fourteen. For a doctor, a model with five inputs is easier to understand and to use, since fewer measurements are needed. Fewer features also mean less risk of over-fitting on a small dataset of seven hundred sixty-eight patients. This is a real benefit of selection, even when the score does not increase. Whenever you can match the score with fewer features, take the simpler model.
