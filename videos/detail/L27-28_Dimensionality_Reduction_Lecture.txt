#0
Let me tell you why we study this topic. Earlier we saw that too many features cause trouble: they are redundant, they make the space empty, and they make models over-fit. Feature selection answers this by dropping columns. Dimensionality reduction answers by combining columns into a few new ones that keep most of the information. In these lectures we cover the main tools, principal component analysis, linear discriminant analysis, and two methods for pictures, t-SNE and UMAP, and learn when to use each one.
#1
Let me add the plan in plain words. Lecture twenty-seven is unsupervised: no labels, just compress and understand the structure. Lecture twenty-eight brings in labels, and also drawing pictures of high-dimensional data. The wine dataset is a good choice: eleven numeric measurements for each wine, a red or white type, and a quality score. Eleven features are too many to plot, but few enough that we can follow every step. Keep this example in mind as we go.
#2
Let me explain with a simple example. Suppose you want to predict the weight of a person, and you give the model height in centimetres and also height in inches. These are two columns with the same information, so the model cannot decide how to split credit between them. This is multicollinearity. In a regression, the coefficients can become very large and of opposite signs, and change a lot when you add a few rows. The variance inflation factor tells you how bad it is, because it measures how well each feature can be predicted from all the others together.
#3
Let me explain these thresholds. A value of fifteen point nine means that about ninety-four percent of the density information can be predicted from the other features, since one minus one over fifteen point nine is about point nine four. After dropping density, the remaining features have values below three, which is acceptable. The other approach, PCA, creates new features that are uncorrelated by construction, so their VIF is exactly one. Which is better depends on whether you need the original feature names, for explanation, or only good predictions.
#4
Let me explain with a picture in your mind. Imagine a scatterplot of height against weight, where the points form a tilted oval. The long axis of the oval is the first principal component, since the data varies the most along it. The short axis, at right angles, is the second. If the oval is very thin, almost all the information is along the first axis, and you could describe each person with just one number, the position along it. PCA does this in many dimensions, finding the best few axes. Note that the axes are linear combinations of the original features.
#5
Let me explain with the numbers. Total sulfur dioxide ranges over hundreds of milligrams per litre, and density varies in the third decimal place. Without scaling, PCA treats the variance of sulfur dioxide as the most important simply because the numbers are large. The first component becomes almost entirely sulfur dioxide, explaining ninety-five percent, which tells us about units and not about wine. After standardising each feature to a standard deviation of one, every feature gets an equal start, and PCA finds the real structure. Remember that scaling is not optional for PCA.
#6
Let me explain each rule. The scree plot shows the variance explained by each component in order, and you look for the bend where the bars stop dropping quickly. The Kaiser rule keeps components with an eigenvalue above one, meaning they explain more than one original standardised feature would. The cumulative rule keeps enough components to reach a target such as ninety percent. They do not always agree, and the choice depends on your purpose. For a picture, two or three components is enough, and for modelling you might use the cumulative rule and check the score.
#7
Let me explain how to read loadings. After fitting PCA in scikit-learn, the attribute components underscore is a matrix, with one row per component and one column per feature. Put it in a data frame, with the feature names as columns. For each component, sort by the absolute value, and read the top features and their signs. A positive and a negative sign on different features means the component is a contrast between the two groups. Giving each component a short descriptive name helps you explain it to others.
#8
Let me explain why this result is impressive. We never told PCA which wines were red or white. We only gave it chemical measurements. Yet the first component separates the two types, because red and white wines are made differently, and that shows up in many chemical measurements at once. This is the real value of PCA as an exploratory tool: it can reveal structure that you did not ask about. Whenever PCA gives a component that matches a known variable, it is a good sign that the component is meaningful.
#9
Let me give an example of the reading. If the arrows for free sulfur dioxide and total sulfur dioxide point in almost the same direction, wines high in one are high in the other. If the arrow for alcohol points the opposite way from density, wines with more alcohol tend to be lighter. If a point lies near the tip of an arrow, that wine has a high value for that feature. A biplot only shows two components, so features whose arrows are short are not well represented in this picture, and you should check the other components for them.
#10
Let me explain the change of focus. Everything in lecture twenty-seven ignored the target. Now we have a goal: to separate known groups, for example low, medium and high quality wines. The directions that carry the most variance are not necessarily the directions that separate the groups, so a method that uses labels can do better. And then there is a different goal: drawing a picture to see whether clusters exist. These are different tasks, and different tools suit them, as we will see.
#11
Let me explain the idea in words. LDA looks for the direction in which the class means are far apart, relative to the spread within each class. Projecting onto that direction separates the classes as much as possible. Because it needs the labels, it is a supervised method, and it can also be used directly as a classifier. The limit on the number of components follows from the geometry: with three classes, the three class means lie in a plane, so two directions are enough. In scikit-learn, LinearDiscriminantAnalysis with n components equal to two does this.
#12
Let me explain how to read the numbers. The baseline of always guessing the most common class is forty-three point six percent. Two PCA components get forty-eight point six, only a little better, because PCA did not look at the quality labels. Two LDA components get fifty-seven point seven, because they were chosen to separate those labels. That is a fair comparison, because both use two dimensions. The message is: use PCA for understanding and compression, and LDA when your goal is to separate known classes, remembering that LDA must be fitted on the training data only.
#13
Let me explain what to watch out for. t-SNE and UMAP produce beautiful pictures, and that is the danger. Distances between clusters in the picture are not reliable, the size of a cluster does not mean its real spread, and a different random seed or a different perplexity can produce a different layout. Also, they cannot be used as a step in a model pipeline in the usual way, because t-SNE has no transform for new points. Use them for looking, and then confirm any pattern with numbers, for example with clustering metrics or PCA.
#14
Let me explain this table in a sentence each. Variance inflation factor tells you which features are redundant. PCA is the default for compression, and its loadings explain what each component means. LDA is the choice if you have class labels and want the best separation. t-SNE and UMAP are for exploring, drawing, and presenting clusters. When you build a model, use PCA or LDA inside a pipeline, fitted on the training data only. If a question asks which method you would use, name the goal first, and then the method.

Let me suggest a practice task. Take a dataset with at least eight numeric features. Compute the VIF of each, and decide what to drop. Scale, then run PCA, draw the scree plot, and choose the number of components with two rules. Print the loadings, and name the first three components. If your data has class labels, fit LDA, and compare a classifier on two PCA components and two LDA components.
