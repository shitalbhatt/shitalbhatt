#0
Let me tell you what you need for this lab. You need Python with the libraries PIL, numpy, matplotlib and scipy, and any small photo and short audio clip, such as a wave file. Everything we do uses the ideas from the lecture, only now we run them. The surprise for many students is how little new code there is. After the first line that loads a file, you are working with an ordinary numpy array, and all the tools you already know apply.
#1
Let me add one thing to remember for each. For an image, the shape tells you height first, then width, then channels, which is the opposite of the usual width by height used in photo software. This catches many people out. For audio, the sample rate is not a property of the numbers themselves. It is metadata that tells you how fast they were recorded, so you must keep it with the array. If you lose it, you cannot tell how long the sound lasts or what pitch it has.
#2
Let me explain the steps in code. Import Image from PIL, call Image dot open with the file name, then wrap it with numpy dot array. Print the shape, the data type, the minimum and the maximum. The data type should be an unsigned eight-bit integer, so values range from zero to two fifty five. If you see a fourth channel, it is transparency, called alpha. This quick check is the same as df dot info for tables, and you should do it every time before you plot.
#3
Let me explain how to read the spikes. If the sky is a flat blue, thousands of pixels share almost the same value, so one narrow tall bar appears in the blue channel. Natural textures such as grass or skin vary more, so they give wider, smoother humps. A histogram that is all squeezed to the left means a dark image, and squeezed to the right means a bright one. Try changing the brightness of the image by adding fifty to every value, clipped at two fifty five, and watch the histogram slide to the right and pile up at the end.
#4
Let me explain the time axis. The sample index runs from zero to forty four thousand one hundred, and dividing each index by twenty two thousand fifty gives a time in seconds from zero to two. That is why the clip lasts two seconds. Using scipy dot io dot wavfile dot read gives you both the rate and the array in one call. Sixteen-bit integers range from minus thirty two thousand seven hundred sixty eight to thirty two thousand seven hundred sixty seven, so you can divide by thirty two thousand seven hundred sixty eight to scale the amplitude between minus one and one.
#5
Let me give more details. Windows of a hundred milliseconds at twenty two thousand fifty hertz contain about two thousand two hundred five samples each. Taking the mean of the absolute value inside each window gives a smooth loudness curve called an envelope, and it makes patterns like a pluck, a decay or a repeated beat easy to see. In pandas you could also use rolling with a window of that size. The important idea is that audio, like monthly sales, is an ordered list in time, so the same smoothing tools apply.
#6
Let me summarise the routine so that you can reuse it. Load, convert to numbers, check the shape and the range, plot the distribution, and then look for anything strange. In an image project, strange might be a spike at zero because of black borders, or an image with the wrong number of channels. In an audio project, strange might be clipping at the maximum, long silence, or the wrong sample rate.
