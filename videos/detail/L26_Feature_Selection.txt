#0
Let me explain why we select features even after building them carefully. Every column has a cost: it makes the model slower, harder to explain, and more likely to over-fit. Selecting does not mean throwing away information blindly. It means keeping the smallest set of columns that gives nearly the same predictive power. There are three families of methods, and each answers the question a little differently. Learn the idea of each, and then you can choose the one that suits your problem and your time.
#1
Let me explain each with the examples. For variance threshold in scikit-learn, you set a minimum variance, for example point oh one, and columns below it are dropped. For Pearson correlation, you compute the correlation of each feature with the target and keep the top ones. For the ANOVA F-test, SelectKBest with f classif ranks numeric features against a class target. For mutual information, mutual info classif can also find non-linear relationships. The strength is speed, and the weakness is that each feature is judged alone, so two features that carry the same information will both score high.
#2
Let me explain what this result shows. The top eight features contain five that are essentially the same idea, the page value signal, in different forms. A filter does not notice, because it scores each column separately. So the model receives five copies of one message and fewer different messages. Meanwhile, a feature like November, which does not stand out alone, can still help a model in combination with others. This is the main limitation of filters, and why we use them for a first screen and not the final decision.
#3
Let me explain with an analogy. Forward selection is like building a cricket team by picking the best player first, then adding whoever improves the team most, one by one. Backward elimination starts with a full squad of fifty and drops the player who is least missed. Recursive feature elimination uses the model's own weights to decide who goes. In scikit-learn, RFE and SequentialFeatureSelector implement these. They give better subsets, but training hundreds of models takes time, and if you use the same data for selecting and scoring, you can over-fit the selection itself.
#4
Let me explain the penalty. In L one logistic regression, the loss includes a term proportional to the sum of the absolute values of the coefficients. To reduce this term, the model sets many coefficients exactly to zero, so those features are dropped automatically. The setting C is the inverse of the penalty strength, so a smaller C means a stronger penalty and fewer features. For trees and forests, feature importances in scikit-learn show how much each feature reduced impurity across all splits. A caution: impurity importance can favour features with many distinct values, so check with permutation importance when it matters.
#5
Let me explain how to choose. If you have thousands of features and need a quick cut, use a filter. If you have a short list and want the best subset, use a wrapper. If you want a sensible default that works in one training run, use an embedded method such as L one, or a tree importance. In practice, people often combine them, using a filter to cut the list, then an embedded method to finish. The table is a quick summary, and you can use it in viva questions.
#6
Let me explain the leakage point with an example. Suppose you choose the best twenty features using the whole dataset, and then split into train and test. The selection step has already seen the test labels, so the features chosen are the ones that happen to correlate with the test answers as well, and your test score will be too high. The correct way is to split first, select using only the training rows, and evaluate on the test rows. Putting the selector inside a scikit-learn pipeline, before the model, does this automatically, also inside cross-validation.
