#0
Let me tell you why this lecture is important. Most real datasets have columns made of words: city, product type, job title, payment mode. Before a model can use them, we have to turn them into numbers, and the way we do that can help or hurt. In the second part we look at a very common situation: one class is much rarer than the other, such as fraud, disease or churn. You will see that a model with high accuracy can still be useless.
#1
Let me add a note about the order. First, the question of what the categories mean, because that decides the encoding. Then the main techniques, from the simplest to the most flexible. Then the problem of too many categories. And finally the rare-class problem, which is about the target column, not the features. In the lab, you will run each one on the Airbnb data, and compare their effect on a model, so keep an eye out for which encoding is best for which situation.
#2
Let me explain the idea with a classroom example. Suppose a model predicts marks from the branch of the student. If you give it the words, it cannot compute. If you give it one for computer science and two for electronics, it will think electronics is twice computer science, which has no meaning. Encoding is the step where you convert words to numbers in a way that keeps the meaning and does not add false meaning. Tree-based models are more forgiving, but linear models, K nearest neighbours and neural networks are sensitive to it.
#3
Let me give you examples for each. Nominal: city, gender, payment mode, colour. Ordinal: education level from school to doctorate, customer rating from poor to excellent, and the size of a T-shirt. Binary: yes or no, weekend or weekday. A column of ratings stored as one to five is already ordinal-encoded, which is fine. A column with city names stored as one to five is a trap, because the numbers suggest an order. Always ask what the column means, and not only what it looks like.
#4
Let me explain it with the example. After label encoding, a linear model would learn a single weight for the borough number. If the weight is positive, it says that higher codes mean higher prices, so Staten Island with code four would be priced twice as much as Manhattan with code two. This is nonsense. But a decision tree can split the codes into groups, such as zero and one in one branch, and two to four in another, so it can work around the problem. In scikit-learn, LabelEncoder is meant for target columns. For features, use OrdinalEncoder or OneHotEncoder.
#5
Let me explain how to write the order. In pandas, create a dictionary such as shared room to zero, private room to one, entire home to two, and apply it with df of room type dot map. In scikit-learn, OrdinalEncoder takes a categories argument with the lists in the right order. The check on the median price is a useful sanity check: if the encoded values rise with the target, the order is sensible. Remember that ordinal encoding still assumes equal gaps between steps, which is not always true, so treat it as an approximation.
#6
Let me explain the cost. For five boroughs, you get five new columns, and for each row, exactly one is one. In pandas, pd dot get dummies with the column name does this. In scikit-learn, OneHotEncoder with handle unknown equal to ignore is the right choice for pipelines, because it can deal with a category that was not seen during training. The price you pay is more columns, so a column with a thousand categories would add a thousand columns. That is the reason for the next slides.
#7
Let me explain the trap with a small example. Suppose you have only two categories, male and female. If you keep both columns, the second is just one minus the first, so they are perfectly collinear. In a linear regression, the model cannot separate their effects, and the coefficients become unstable, which is multicollinearity from module two. Dropping one column removes this. It means each remaining dummy is read as a difference from the baseline. In scikit-learn, you can set drop equal to first. Tree models do not need this, but it is harmless.
#8
Let me explain frequency encoding more. Count how many rows each category has, divide by the total, and map this share back. Rare areas get small values, and popular areas get large ones, so the model learns that popularity matters. The drawback is that two different areas with the same share get the same value. For the target, a multi-class column such as room type with three categories is label-encoded, because classifiers expect class labels, and the order has no meaning for them.
#9
Let me explain the first rule with an example. Suppose you compute the median price for each area using all rows, and then split into train and test. The test rows have already contributed to the encoding, so the model has seen a trace of the answers, which is leakage, and the test score will look better than it should. So compute the encoding on the training rows only, and apply it to the test rows. The second rule is smoothing: for small groups, blend the group median with the overall median, so a single expensive home does not distort a whole area.
#10
Let me explain this with the numbers. If ninety-seven point six percent of homes are not shared rooms, a model that never predicts a shared room is ninety-seven point six percent accurate for that question, and it is completely useless. That is the accuracy paradox. For a bank, a model that says no fraud for every transaction has an accuracy of ninety-nine percent if fraud is one in a hundred, but catches no fraud. Always look at the class counts first, and at recall and precision for the rare class.
#11
Let me explain each in a line. Stratify means the train and test sets keep the same class proportions, using stratify equal to y in train test split. Class weights tell the model that mistakes on the rare class cost more, with class weight equal to balanced. Resampling can duplicate rare rows or remove common ones, but only do this on the training data, otherwise the test set contains copies of training rows. SMOTE, a popular method, creates synthetic rare rows. And evaluation must use recall for the rare class, the F one score, or the area under the precision-recall curve.
#12
Let me close with a decision routine for any categorical column. Count the categories. Is there an order? If so, map it yourself. If not, and there are a few categories, one-hot with the first dropped. If there are many, try frequency or target encoding, with care. Then look at the target, and if one class is rare, stratify, set class weights, and report recall. In the lab, you will see these choices change the model scores. Thank you for watching.
